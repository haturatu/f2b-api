Строка `Googlebot` в User-Agent не доказывает, что запрос действительно пришёл от Google. При анализе записей jail `fake-googlebot` нужно проверять исходный IP.

## Проверка с помощью DNS

Сначала выполните обратный DNS-запрос и получите имя узла. Затем сделайте прямой запрос для этого имени и убедитесь, что ответ содержит первоначальный IP.

```sh
host 66.249.66.1
host crawl-66-249-66-1.googlebot.com
```

Это пример из [официальной документации Google](https://developers.google.com/crawling/docs/crawlers-fetchers/verify-google-requests). В реальном случае используйте IP из журналов и полученное для него имя. Для IPv6 проверьте запись AAAA.

Google документирует суффиксы `.googlebot.com`, `.google.com` и `.googleusercontent.com` для разных типов краулеров. Проверяйте соответствующий тип и границу доменного имени: одной подстроки `googlebot.com` недостаточно.

## Различия между источниками

В [политиках по сервисам]({{< relref "/policies/services.md" >}}) указано, что `freebsd` проверяет обратную запись и совпадение прямого разрешения. В `oci` проверяется только суффикс имени из обратного DNS. Одинаковое имя jail не означает одинаковую надёжность проверки.

Классификация проверенных ботов Cloudflare может помочь, но не следует доверять только User-Agent. Важно не блокировать настоящих краулеров и не разрешать поддельные запросы.
