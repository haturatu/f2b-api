本页说明观测数据背后的阻断策略，并解释其评估方式。

## 当前配置

本页汇总截至 2026 年 11 月 1 日的当前配置，供公开参考。采集源标识为 `freebsd` 与 `oci`。两者各自使用 15 个 jail：6 个用于传统服务，9 个用于扫描器缓解。

## 两种评估方式

| 方式 | 适用范围 | 阻断判据 |
| --- | --- | --- |
| 重复检测 | SSH、邮件认证、HTTP、重复违规者 | 在配置的检测窗口内命中的次数 |
| 单次检测 | 配置的 HTTP 扫描器特征 | 单次命中即永久封禁 |

此处的“命中”指某条日志行匹配了 jail 的过滤规则。由于聚合与排除设置，命中数可能与简单的请求次数不同。

## 扫描器共用设置 {#shared-scanner-settings}

```ini
maxretry = 1
findtime = 10m
bantime = -1
bantime.increment = false
```

配置的九个 jail 在单次命中后即永久封禁。`bantime = -1` 表示不会自动到期。10 分钟的检测窗口并不代表封禁持续时间。

阻断范围覆盖 80 与 443 端口上基于 TCP 和 UDP 的 HTTP/HTTPS。`freebsd` 通过 PF 实施，`oci` 通过 nftables 实施。检测与防火墙执行均在各自采集源的 Fail2ban 中运行；本公开 API 不发布阻断指令。

## 依赖环境的判断

在合法使用管理界面、WebDAV、WordPress、PHP 或扩展 HTTP 方法的服务上，同样的请求可能是正常的。此处列出的条件是各采集源的运行标准，并非可以原样套用到任何站点的推荐设置。

管理用排除网络、端点、凭据以及内部日志内容均不公开。公开说明与各服务器上管理的完整配置是分别维护的。
