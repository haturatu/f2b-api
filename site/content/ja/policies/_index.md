Fail2ban は設定されたログの条件に一致すると IP を BAN します。

ただ、検知の仕方は全部同じではありません。SSH の認証失敗などは一定期間内の回数を見ていますが、スキャナーによくあるリクエストは一度の一致で永久 BAN にするものもあります。

この API のデータを使うなら、まずこの違いを把握しておく必要があります。

## 現在の構成

2026 年 11 月 1 日に確認した設定では、収集元の公開ラベルは `freebsd` と `oci` です。それぞれ合計 15 個の Jail を使用し、サービス向けが 6 個、スキャナー対策が 9 個です。

ここに書いているのは**その時点の運用設定**です。どのサーバーでもそのまま使える推奨値という意味ではありません。

## 検知の仕方は大きく二つ

| 方式 | 対象 | BAN の条件 |
| --- | --- | --- |
| 回数で判定 | SSH、メール、HTTP、再犯など | 一定の検知期間内に指定回数一致 |
| 一度で判定 | 特定の HTTP スキャナーの特徴 | 1 件の一致で永久 BAN |

ここでいう「一致」はアクセスが 1 回あったという意味ではなく、Fail2ban のフィルターにログ行が一致したことです。除外設定やログの作りによっては、実際のアクセス回数と一致しません。

## スキャナー対策の共通設定

9 個のスキャナー対策 Jail は、次の設定を使っています。

```ini
maxretry = 1
findtime = 10m
bantime = -1
bantime.increment = false
```

`maxretry = 1` なので、指定したフィルターに 1 回一致すると BAN します。`bantime = -1` は自動解除しないという意味です。 `findtime = 10m` は検知の時間幅であって、10 分で解除されるわけではありません。

遮断するのは HTTP / HTTPS の TCP・UDP 80 / 443 番ポートです。`freebsd` は PF、`oci` は nftables で適用します。

ちなみに、**この API が BAN 命令を配信しているわけではありません**。各サーバーの Fail2ban が検知から遮断まで実行し、API は結果を収集して公開するだけです。

## そのまま別のサーバーに入れるのはおすすめしない

例えば WebDAV を使っているサービスなら、WebDAV の HTTP メソッドは正常です。WordPress や PHP の管理画面、独自の認証 API でも同じことが言えます。

特定の URL や User-Agent がスキャナーっぽく見えても、正当なアクセスの場合があります。なので、ここで紹介する条件はあくまでも**収集元で採用している遮断基準**として読んでください。

内部の除外ネットワーク、接続先、認証情報、生ログなどは公開していません。実際のサーバー設定と公開用の説明も分けています。
