この API のデータで少し紛らわしいのが、**「過去に観測した」と「現在 BAN されている」は別**ということです。

そもそも収集はリアルタイムではありません。IP の一覧をそのまま攻撃者リストとして使う前に、どんな形で記録しているのかを確認してください。

## 観測の単位

1 件の観測は `source`、`jail`、`ip` の組み合わせです。

例えば同じ IP が SSH と Nginx で検知されれば、別々の観測として残します。二つの収集元で同じ IP が記録された場合も同様です。

そのため、統計の `observations`（観測件数）と `ips`（重複を除いた IP 数）は一致しない場合があります。テキストフィードでは IP の重複を除いて出力します。

## 時刻と BAN の状態

| 項目 | 意味 |
| --- | --- |
| `first_seen` | この収集基盤で最初に確認した時刻 |
| `last_seen` | 最後に確認した収集時刻 |
| `active = 1` | 最新のスナップショットの BAN 一覧にある |
| `active = 0` | 後続のスナップショットで一覧から外れた |
| `stale = 1` | Jail の収集が 48 時間を超えて更新されていない |

時刻は Fail2ban が BAN を実行した瞬間ではなく、**この仕組みが観測した時刻**です。実際にはいつから BAN されていたのか、これだけでは分かりません。

また、収集が止まったことと BAN が解除されたことも別です。更新されなくなった Jail は `stale` として扱い、現在有効な一覧・統計・フィードから除外します。過去の記録は検索や `active=all` で確認できます。

## 定期収集で分からないこと

収集元では日次のレポート生成と合わせて、現在の BAN 一覧を JSON にしています。前回と内容が同じならハッシュを使った heartbeat、変更があれば完全なスナップショットを送り、その差分を保存します。

つまり、収集から次の収集までの間に BAN されて解除された IP は記録できません。**Fail2ban の全イベントをリアルタイムに追いかけているわけではありません。**

記録されているのも、この収集基盤が観測を始めた以降のデータだけです。

## 国・ASN・組織について

国や ASN、組織は GeoIP、RDAP などで付けたネットワーク情報です。分からない場合は `null` になります。

IP の国情報が日本だからといって、アクセスした人物が日本にいるとは限りません。まして国籍や居住地、個人の特定に使える情報ではありません。

## 公開範囲と誤検知

公開するのは IP、収集元のラベル、Jail、観測時刻、状態、ネットワークの付加情報です。生のログ、リクエスト本文、ユーザー名、認証情報、管理用の除外リストは公開していません。

**IP が記録されたことだけを理由に、別のサービスで永久 BAN するのは避けてください。** 共有 IP や再割り当ての問題もあるので、[検知条件]({{< relref "/policies/_index.md" >}})と観測時刻を合わせて確認する必要があります。

解釈の誤りや仕様の問題は [GitHub リポジトリ](https://github.com/haturatu/f2b-api)で報告できます。ただし、認証情報や生ログ、個人情報を Issue に貼り付けないでください。
